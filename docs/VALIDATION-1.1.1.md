# v1.1.1 · KANALI 2:1 交付画幅修正

日期：2026-11-03。用户在实际 KANALI 上传界面确认需要 2:1 画幅；v1.1.0 使用的 2240×1080 会再次触发裁切。官网面板标称尺寸不能代替软件上传窗口。新交付统一为 **2160×1080、方形像素（SAR 1:1）、显示比例 2:1**。

## 修正范围

- `mapper/output.py` 作为交付尺寸的唯一后端定义；GPU、Blender、编码器能力探测及校准网格共同使用。
- Blender 同时修改输出像素、展开网格宽高比和正交相机宽度，2× 为 4320×2160。
- FFmpeg 的 MP4 和 FFV1 路径均显式 `setsar=1`。仅将2240缩到2160会可能产生SAR 28:27，使实际显示比例仍然错误。
- 前端展开预览与标签读取 API `output_profile`。曲面毫米参数、眼位和已有预设保持独立。
- 校准图片改为按尺寸命名的 `calibration-2160x1080.png`，避免继续复用旧2240网格。
- 500 MB 严格验收、自动预算重编码、硬件回退等规则不变。

## 回归与真实输出

127 项 Python 测试、4 套 Node 测试通过。新增测试覆盖 PNG/raw × H.264/FFV1 四条真实编码路径，从非2:1输入转换后检查2160×1080、SAR1及有效DAR2，四边24像素彩色标记全部保留。故障注入确认：去掉`setsar=1`或增加中心裁切，四条测试都能拒绝错误结果。

## 旧成片与验收边界

旧2240成片不能直接左右裁掉80列，否则会丢失曲面映射对应的屏幕边缘。优先从原素材重新导出；若保留既有映射，应对最早的高质量候选做整幅Lanczos缩放到2160×1080并设SAR1，再验收体积。不要把旧展开成片当普通源视频重新做一次曲面映射。

以上为软件编码、几何与成片回放验证。真实KANALI界面的最终导入仍由用户实机确认，不能据本轮结果推断所有KANALI版本或其他型号均相同。
