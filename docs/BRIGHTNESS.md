# 实验性视角亮度补偿

v1.2.0 加入可选的角度亮度补偿，用于尝试减轻“从目标眼位观看时，圆弧中央比两侧平面更亮”的现象。功能**默认关闭**，只对较亮区域做压暗，不提亮较暗区域。它需要实机手动校准，不能从 AMOLED 材质名称自动得出准确参数。

输出仍为 **2160×1080、2:1、SAR 1:1**；最终 MP4 仍需严格小于 **500,000,000 字节**。亮度补偿不会改变裁切范围、几何映射、画布比例或体积验收规则。

## 开始使用

1. 先关闭亮度补偿，按 [几何校准指南](CALIBRATION.md) 设置屏幕形状和观看位置，尤其是弯折中轴、俯视角与距离。用多平行直线测试确认几何对齐后再调整灰卡亮度，避免用亮度参数掩盖几何错误。亮度模型使用同一眼位和曲面法线。
2. 开启“实验性亮度补偿”。初值为掠射角相对亮度 **60%**、曲线指数 **2**、肩部形状 **1**、补偿强度 **100%**。这些数值仅供开始调节，**不是物理推导结果，也不是 TRYX 面板实测值**。
3. 对照曲面展开图：它显示加入补偿后的真实预处理像素，通常圆弧附近会比两翼暗。放到曲面屏后，目的是用这部分压暗抵消圆弧原本更亮的观察效果。
4. 目标眼位预览可以单独勾选“模型模拟”，额外模拟屏幕角度衰减。这个勾选项只帮助观察预测结果，**不写入导出**，也不改变补偿参数。未勾选时，预览不会假装屏幕具有该角度衰减。
5. 按下面的灰卡流程校准，然后用自己的视频导出短片，检查肤色、高光、边框和暗部，再做完整导出。

浏览器模拟只能说明参数在所选模型内是否一致。强度为 100% 时，均匀灰卡在开启模型模拟的目标眼位预览中应趋于均匀；这不证明真实屏幕也符合该模型。

## 用实机灰卡调参

“亮度校准灰卡”提供全幅 **RGB(128,128,128)** 中性灰素材，可通过 `POST /api/brightness-calibration {}` 载入。这里的 128 是 8 位编码值，不是 50% 的线性亮度。灰卡与输出画布同为 2:1。

1. 固定实际屏幕亮度、环境照明和观看位置，关闭会改变画面的附加滤镜或信息叠加。拍照比较时锁定曝光和白平衡，避免自动曝光掩盖差异。
2. 载入灰卡，使用**铺满取景**模式，确保没有立牌边框、底座或未覆盖区域。先关闭补偿导出短片，记录圆弧中央与两翼的亮度差异。
3. 开启补偿，保持强度 100%，从 60% / 指数 2 / 肩部形状 1 开始重新导出。KANALI 使用完整单画布显示，不要再裁切或缩放。
4. 若中央仍比两翼亮，降低“掠射角相对亮度”，让模型假定更强的角度衰减；若中央比两翼暗，则提高这个值。调整曲线指数可改变中间角度的过渡形状，应在中心、过渡带和两翼一起比较。
5. 若中央与两翼接近，但两侧过渡带仍偏亮，可逐步提高“肩部形状”，例如从 1 调至 1.5、2；若过渡带反而变暗则回调。每次同时复查中央、两翼及过渡带，因为有限眼位下的最暗响应也可能变化。过量补偿会把亮带变成暗带。
6. 当灰卡尽量均匀后，换回真实视频。若更重视总体亮度，可降低“补偿强度”，接受部分剩余亮度差；不要把强度当作实测曲线参数。

中灰有助于减小满白画面对功耗限亮的影响，但不能排除它。建议用数种灰阶和实际片段复查。若需要测得面板本身的角度曲线，应测量同一发光区域在不同观察角下的亮度，避免把不同位置的面板均匀性差异混进角度效应。NIST 的 OLED 表征同时测量角向强度、色度、空间亮度均匀性，并考察工作条件对结果的影响。[NIST：Optical Measurements of OLED Panels for Lighting Applications](https://www.nist.gov/publications/optical-measurements-oled-panels-lighting-applications)

## 曲面两侧残留细亮线意味着什么

仅凭“中央和两翼相近，过渡带却出现两条细亮线”，不能判定是弧长范围不足，更不能据此认定屏幕故障。原模型只用最低亮度与一个指数描述角度曲线：即使中心和翼面两个参考值匹配，中间角度的响应及变化速率仍可能不匹配。实际曲面的法线分布、弯折中轴错位、光学结构或面板空间不均匀，也可能形成残差。

一个模型例子：设 `m=0.6, p=2`，肩部形状 1 和 2 在正视与 45°时都分别给出 100% 和 80%，但在 30°时分别为 90% 和 96%。若实际响应接近后者而按前者补偿，中间角度仍可能比中心和翼面亮约 6.7%。这说明增加独立的肩部形状参数有用；它不证明用户的屏幕恰好服从这组参数。

先用无亮度补偿的平行线测试校准几何，再用中灰校准角度响应。也应对比关闭补偿时的灰卡，并小幅改变眼位：若细线固定在面板位置、没有随观察角度呈合理变化，就需要考虑空间均匀性或反射等因素，单一角度模型可能无法处理。改变实际几何弧长会同时改变视频映射，不宜仅为消除亮线而把已经正确的直线再次调弯。

很短的圆弧配合很陡的肩部参数，还会放大有限网格的插值误差。启用有效亮度补偿时，预览和导出会检查圆弧内的横向采样密度；不足时仅在渲染假设的弯曲区自动补充采样，最多增加 65 列。GPU 和 Blender 使用同一规则，默认参数密度已足够时不改变网格。这减少的是计算采样残差，**不能代替实屏校准，也不能修复错误的几何或面板响应模型**。8 位导出的量化与视频压缩仍可能留下小差异。

## 参数与补偿公式

设置保存在几何参数中，旧预设未包含这些键时使用以下默认值：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `brightness_enabled` | `false` | 是否对导出和预处理预览启用补偿 |
| `brightness_floor` | `0.6` | 模型在趋近 90°掠射角时，相对正视方向的亮度极限 |
| `brightness_power` | `2.0` | 角度曲线指数，控制中间角度的衰减形状 |
| `brightness_shoulder` | `1.0` | 肩部形状，范围 0.25–8；1 精确保留旧曲线，改变中间过渡陡峭度 |
| `brightness_strength` | `1.0` | 补偿混合强度；0 不补偿，1 为完整补偿 |

对屏幕位置 `P`，取外表面单位法线 `n`，以及从 `P` 指向目标眼位的单位向量 `v`：

```text
mu = clamp(dot(n, v), 0, 1)
t  = mu^p
T  = t^k / (t^k + (1-t)^k) # k=1 时直接使用 T=t，保持旧模型
A  = m + (1 - m) * T
R  = min(A_at_four_corners) # 当前凸曲面四个物理角点的最低模型亮度
g  = 1 + strength * (R/A - 1)
output_linear_rgb = input_linear_rgb * g
```

其中 `m = brightness_floor`、`p = brightness_power`、`k = brightness_shoulder`。观察角是眼睛方向与**局部屏幕法线**的夹角：0°为正对发光面，90°为沿表面方向观看。眼位高度、有限观看距离及弯折中轴位置都会改变各位置的 `mu`。

`k` 始终保留单调响应，且固定 `t=0, 0.5, 1` 的三个锚点。`k>1` 使近正视一侧的响应更平、随后下降更集中；`k<1` 使这种过渡更缓。它调整的是角度响应形状，**不移动实际曲面或在固定像素位置绘制两条遮罩**。中间锚点只有在 `p=2` 时恰好对应 45°；改变 `p` 后，不应理解成所有情况下都保持 45°亮度不变。

对于当前支持的凸形竖直拉伸屏幕、以及通过检查的正面眼位，最暗响应必定位于四个物理角点之一，因此 `R` 由这四点精确求得，**与素材裁切、取景、网格分辨率及每帧画面内容无关**。它随屏幕几何、眼位或模型参数调整而更新，不会随视频内容逐帧波动。强度 1 时，模型下的观察亮度系数满足 `A * g = R`；强度 0 时，`g = 1`。因为 `g ≤ 1`，算法仅压暗较亮区域，代价是降低全局可用峰值亮度。没有提亮模式，也不会通过提高增益弥补最暗区域。

默认参数的模型示例为：

| 与局部法线的夹角 | 0° | 45° | 60° | 趋近 90° |
| --- | --- | --- | --- | --- |
| 相对亮度 `A` | 100% | 80% | 70% | 60% |

这些是公式计算值。实际屏幕还包含俯视、近距离等因素，因此不能仅凭“水平观察 45°”认定全屏最低亮度就是 80%。

GPU shader 与 Blender 材质均在线性 RGB 中使用同一标量增益，覆盖源视频以及立牌的边框、厚度和底座等装饰，然后编码输出。相同的 RGB 标量不会主动改变线性颜色比例；显示、量化和编码仍可能产生细小差异。展开预览显示补偿本身；“模型模拟”则在观察预览中额外施加 `A`，用于检查预测均匀性。

## 模型的物理边界

**余弦光强不等于余弦亮度。** 理想朗伯表面的光强随角度满足 `I(theta) = I(0) * cos(theta)`，但投影面积也缩小为 `S * cos(theta)`，因此亮度 `L = I / (S * cos(theta))` 保持不变。不能把这个光强定律直接用作屏幕亮度衰减公式。OLED 实际角分布会因器件结构明显偏离朗伯分布。[Archer 等：Accurate Efficiency Measurements of Organic Light-Emitting Diodes via Angle-Resolved Spectroscopy](https://advanced.onlinelibrary.wiley.com/doi/10.1002/adom.202000838)

这里的 `A` 是一个**非朗伯角度亮度经验模型**。微腔和出光光学结构会改变 OLED 的角向发射；实验中增加扩散层也能改变角分布及视角色偏。因此，仅凭 AMOLED 名称或宣传图无法确定本屏的 `m`、`p`、`k`，也不能保证所有面板都按单调曲线衰减。[Scientific Reports：Enhanced light extraction efficiency and viewing angle characteristics of microcavity OLEDs by using a diffusion layer](https://www.nature.com/articles/s41598-021-82753-9)

90°处的 `m` 是拟合曲线的极限参数。严格沿屏幕表面观看时，投影面积趋于零，不能把 90°当作可直接读取普通画面的测量方向。“60%”没有对应的厂家承诺或已知实测依据。算法也**不乘距离平方反比因子**：对可分辨的屏幕表面，这不是正确的表观亮度补偿方式。

当前功能假定角度变化主要影响亮度且颜色基本不变，不补偿视角色偏、机箱玻璃反射或眩光、功耗限亮（ABL）、温度和时间漂移、面板自身不均匀。它只针对设置的观看位置；头部移动后，几何与亮度补偿都可能不再准确。若同一组参数无法同时改善不同灰阶或不同场景，应减小强度或关闭本实验功能，而不是把模型模拟当作实机测量结果。
